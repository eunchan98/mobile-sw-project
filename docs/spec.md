## 화면 구조: 하단 탭 4개

### 1. 홈
- 오늘 총 열량과 탄수화물·단백질·지방 합계 카드
- 빠른 기록 버튼 (식사 입력 화면으로 이동)

### 2. 목록
- 상단에 월간 달력
  - 기록이 있는 날은 날짜 아래 점 표시, 선택한 날짜는 핑크 원, 미래 날짜는 흐리게
  - 좌우 화살표로 이전/다음 달 이동
- 달력에서 날짜를 선택하면 아래에 그날 먹은 끼니 카드 목록 표시
  - 날짜 헤더: 날짜, 그날 총 열량, 끼니 수 (예: `11/26 · 1,140kcal · 2끼`)
  - 카드: 사진 썸네일, 음식명, 끼니 종류, 열량
- 카드를 터치하면 상세 화면으로 이동
  - 입력했던 내용 (사진, 날짜/시간, 끼니, 음식별 이름과 섭취량)
  - 영양소(탄·단·지)와 열량 섭취량

### 3. 분석 (최근 1달)
- 한 달 총 칼로리 카드
- 일별 칼로리 막대 차트
- 끼니 종류별(조식·중식·석식·간식/음료) 영양소 도넛 차트

### 4. 설정
- 영양 데이터 출처 (식품의약품안전처 등, 과제 필수 요구)
- 앱 정보

## 식사 입력 화면 (한 화면 스크롤 폼)
1. 음식 사진 (카메라 또는 갤러리)
2. 식사 날짜와 시간
3. 끼니 종류: 입력한 시간으로 자동 제안하고 직접 수정 가능
4. 음식 목록: 한 끼에 여러 음식(밥/국/반찬)을 `+ 음식 추가`로 입력
   - 음식 이름은 100개 음식 DB에서 검색 후 자동완성으로 선택
   - 섭취량(g) 입력
5. 영양소 합계 미리보기 (탄·단·지, 열량)
6. 저장

## 데이터 모델 (초안)
- **Meal (한 끼)**: id, 날짜/시간, 끼니 종류, 사진 URI
- **MealItem (음식)**: mealId, foodId, 섭취량(g)
- **Food (음식 DB, 약 100개)**: 이름, 기준량(100g), 열량, 탄수화물, 단백질, 지방
- 영양소 계산: `섭취량(g) / 100 × 100g당 영양소`

## 과제 기타 요구사항
- 공공 DB(식약처 식품영양성분 DB 등)에서 약 100개 음식 데이터를 확보하고, 출처를 앱에 표시
- 로컬 단위 테스트 12개 이상, Compose UI 테스트 2개 이상
- 제출물: GitHub 저장소, README.md(앱 소개, 설치·실행, 데이터 출처, 역할분담, 팀원별 vibe coding 프롬프트 목록), YouTube 시연 영상

## 역할 분담 (기능별)

**0단계 공통 기반: 본인 담당 (먼저 완료 후 분담 시작)**
- 프로젝트 생성, Material 3 테마 (`Color.kt`, `Type.kt` = Figma 토큰)
- Room 엔티티·DAO: Meal, MealItem, Food
- 음식 100개 데이터 시드, 하단 탭 네비게이션 뼈대
- 공통 컴포저블: MealCard, Chip, TopBar, BottomNav, Button 등

| | A: 기록 담당 | B: 조회·분석 담당 |
|---|---|---|
| 화면 | 식사 기록(입력), 홈 | 식사 목록(달력), 상세, 분석, 설정 |
| 로직 | 음식 검색, 섭취량별 영양소 계산, 끼니 자동 추천, 사진 선택, 저장 | 날짜별 조회, 하루 요약, 30일 합계, 끼니별 분석 |
| 단위 테스트 | 6개 이상 | 6개 이상 |
| UI 테스트 | 입력 화면 1개 | 목록→상세 이동 1개 |

- A/B 중 누가 어느 쪽을 맡을지는 팀원과 정한다.
- 공통 파일(엔티티, DAO, 테마)은 0단계 이후 수정할 때 서로 알리고 바꾼다.
- 각자 `feature/` 브랜치에서 작업하고 PR로 합친다.
